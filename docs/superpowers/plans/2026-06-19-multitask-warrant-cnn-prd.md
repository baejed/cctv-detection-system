## Problem Statement

The CS thesis panel evaluates the system on the strength of its core algorithm. The current algorithmic spine - `sklearn.KMeans` + a 5-input scalar-feature MLP - is undergraduate-coursework ML, not a thesis-grade contribution. The existing `WarrantMLP` predicts only 3 MUTCD warrants (W1, W2, W4) plus a meta `recommended` flag from 5 hand-engineered scalars (`major_volume`, `minor_volume`, `peds`, `vpm`, `phf`), discarding the temporal structure that the CCTV → YOLOv8 → flow-timeseries pipeline produces. A panelist asking *"what is the core algorithm of this system?"* has no compelling answer.

Additionally, the current warrant output answers only *"should this intersection be signalized?"* - it does not recommend richer infrastructure interventions (e.g., road widening) that the Tagum City CTMO needs for capital planning.

## Solution

Replace the existing scalar `WarrantMLP` as the thesis centerpiece with a **multi-task 1D convolutional neural network** that consumes the full per-approach flow timeseries `(`96 slots × 5 channels)` plus intersection metadata, and jointly predicts:

1. **Six warrant probabilities** (multi-label sigmoid head): MUTCD W1, W2, W3, W4 + Tagum-local W-Local 2 (peak concentration) and W-Local 3 (lights off).
2. **A 3-class infrastructure intervention recommendation** (softmax head): `signalize`, `road_widening`, or `timing_only` (= no structural change needed).

The model is trained on a parameter-realistic synthetic dataset (~5,400 intersection-day samples across 30 synthetic intersections) generated by the existing Phase 1 synthetic-traffic plan extended with pedestrian flow, intersection metadata, and ground-truth warrant + intervention labels. Training uses uncertainty-based multi-task loss weighting (Kendall et al. 2018) with 5-seed multi-run evaluation. The existing `WarrantMLP` is retrained on the same data and retained as the baseline the new model is compared against. K-means TOD discovery and Webster's signal timing remain in the system as supporting infrastructure; the new CNN becomes the named algorithmic contribution.

## Implementation Decisions

### Algorithmic centerpiece

- **Architecture:** A 1D convolutional neural network with late-fused intersection metadata. Three conv blocks (channel widths 32 → 64 → 128, kernel size 5, BatchNorm, ReLU, MaxPool×2 after first two blocks, AdaptiveAvgPool after the third), followed by a shared dense layer (size 64) and two task-specific heads: a 6-dim warrant head (multi-label, sigmoid via `BCEWithLogitsLoss`) and a 3-dim intervention head (multi-class, softmax via `CrossEntropyLoss`). Approximately 50K parameters.
- **Inputs:** A `(5, 96)` tensor (channels-first PyTorch convention) of per-slot flow on the four approaches plus pedestrian flow, paired with a 5-element metadata vector. Metadata is passed through a small dense layer (5 → 16, ReLU) and concatenated with the temporal features (128 + 16 = 144) before the shared dense head.
- **Outputs:** 6 warrant logits (`w1, w2, w3, w4, w_local_2, w_local_3`) and 3 intervention logits (`signalize, road_widening, timing_only`). Sigmoid and softmax are applied at inference time, not in the model.
- **Multi-task loss:** Homoscedastic uncertainty weighting per Kendall et al. 2018. Two learnable log-σ parameters; total loss is `BCE / (2·σ_w²) + CE / (2·σ_i²) + log(σ_w · σ_i)`. An equal-weighting ablation is also trained for the results chapter.

> Prototype-derived loss module (the only piece terse enough to require code rather than prose):
> ```python
> class MultiTaskLoss(nn.Module):
>     def __init__(self):
>         super().__init__()
>         self.log_sigma_w = nn.Parameter(torch.zeros(1))
>         self.log_sigma_i = nn.Parameter(torch.zeros(1))
>     def forward(self, bce_warrant, ce_intervention):
>         sw, si = torch.exp(self.log_sigma_w), torch.exp(self.log_sigma_i)
>         return (bce_warrant / (2 * sw**2)) + (ce_intervention / (2 * si**2)) \
>                + torch.log(sw * si)
> ```

### Training procedure

- **Optimizer:** Adam, initial learning rate 1e-3, weight decay 1e-5. Tuned via Optuna (~30 trials) over `lr ∈ [1e-4, 1e-2]`, `dropout ∈ [0.1, 0.5]`, and loss-weight initialization.
- **Schedule:** Up to 100 epochs with early stopping on validation loss (patience = 10). Batch size 64.
- **Regularization:** Dropout 0.3 after the temporal flatten and after the shared dense layer.
- **Class imbalance:** Intervention head uses class-weighted `CrossEntropyLoss` with inverse-frequency weights computed on the training split.
- **Multi-seed runs:** Five training seeds `{0, 1, 2, 3, 4}` per configuration. Final metrics reported as mean ± std with paired t-tests against the baseline.

### Synthetic data extensions (deltas on the existing Phase 1 plan)

- **Pedestrian channel:** Add a 5th input channel to the synthetic flow matrix using realistic Philippine urban patterns (morning, lunch, evening peaks).
- **Intersection metadata generation:** Each synthetic intersection gets `IntersectionMeta(major_lanes ∈ {1,2}, minor_lanes ∈ {1,2}, posted_speed_kph ∈ {30,40,50}, is_signalized ∈ {True,False}, n_approaches ∈ {3,4})` sampled with Tagum-realistic probabilities.
- **Warrant label generation:** Pure-function evaluators apply MUTCD 4C.01–4C.04 thresholds (with low-speed 0.70 multiplier for `posted_speed_kph ≤ 40`) and reuse W-Local 2 and W-Local 3 logic from the existing `server/local_warrants.py` rules.
- **Intervention label assignment:** Deterministic precedence - `road_widening` if post-Webster's critical v/c > 0.90; else `signalize` if `not is_signalized` and any warrant met; else `timing_only`. Webster's is run against K-means-derived TOD chunks (the existing Phase 2 pipeline) on every synthetic day to compute the critical v/c.
- **Dataset shape:** 30 synthetic intersections × 90 days × 2 day-types ≈ 5,400 samples.
- **Dataset split:** Intersection-stratified - ~21 train / 4 val / 5 test intersections. Stratify within each split across metadata profiles using `sklearn.model_selection.GroupShuffleSplit` with `groups=intersection_id`.

### Module changes

- **New ML modules:** A multi-task 1D-CNN model definition and an inference module exposing `predict_recommendations(artifacts, flow_matrix, metadata) → RecommendationResult`, where `RecommendationResult` is a NamedTuple containing `warrant_probs: dict[str, float]`, `intervention: str`, and `intervention_confidence: float`. A multi-task loss module. A training-loop module (loss + optimizer + early stopping + multi-seed orchestration).
- **New rule modules:** Pure-function MUTCD warrant evaluators (`warrant_rules.py`) and an `assign_intervention_label` precedence function (`intervention_rules.py`). Both are DB-free and fully unit-testable.
- **Extended synthetic generator:** Adds pedestrian synthesis, intersection metadata sampling, and per-sample warrant + intervention label emission alongside the existing flow matrix.
- **New CLI scripts:** Training, Optuna hyperparameter search, and evaluation harness (baselines + ablations + saliency).
- **Modified `server/main.py`:** Load the new recommender artifacts in the lifespan alongside the existing `warrant_artifacts`. Both stay loaded; the recommender becomes the production source while the warrant baseline remains callable for comparison.
- **Modified `server/routers/recommendations.py`:** The internal `_analyze` helper switches from `predict_warrants` to `predict_recommendations`. The returned recommendation bundle gains an `intervention` field (`{class: str, confidence: float}`) alongside the existing warrant probabilities.
- **Retained as baseline (no changes):** `server/ml/model.py` (`WarrantMLP`), `server/ml/inference.py:predict_warrants`, `warrant_model.pt`, `warrant_scaler.pkl`. The baseline is retrained on the new synthetic data so the comparison is fair.

### API contract

- The `/recommendations` endpoints return the existing payload shape with one additive change: a new `intervention` field at the recommendation-bundle level, containing `{class: "signalize" | "road_widening" | "timing_only", confidence: float}`. Warrant probabilities continue to be surfaced unchanged in shape but now include the 6 new warrant names; consumers of the old 4-warrant payload must be reviewed for hard-coded warrant names.
- A new optional admin endpoint (out of scope for the first cut, noted in Further Notes) can expose Grad-CAM saliency for a given intersection-day for the thesis figures.

### Architectural decisions

- **Centerpiece-vs-supporting demotion:** K-means TOD discovery (existing Phase 2 plan) is reframed in methods chapter wording as "supporting infrastructure for downstream Webster's timing," not as a co-equal algorithmic contribution. The multi-task CNN is the named contribution.
- **Webster's role:** Webster's stays in production for signal timing and is additionally used at training time to compute the critical v/c that drives `road_widening` label assignment. Webster's is not learned, not replaced.
- **No third algorithm introduced:** This explicitly avoids the "three algorithms to defend" pitfall by folding intervention recommendation into the same multi-task head as warrant classification.

## Testing Decisions

- **Test only external behavior** - model outputs, rule outputs, inference results - not internal layer activations or optimizer step counts. Tests should remain valid if a layer width changes.
- **Warrant rule unit tests** (`tests/test_warrant_rules.py`): Each MUTCD warrant evaluator is tested with hand-crafted `(flow_matrix, metadata)` fixtures known to trigger or not trigger the warrant. Mirrors the existing pure-function tests for W-Local rules in `tests/test_local_warrants.py`.
- **Intervention rule unit tests** (`tests/test_intervention_rules.py`): The precedence function is tested for each of the 3 outcomes and for the three pairwise ties (both widening+signalize-eligible, etc.). Verifies the locked precedence `widening > signalize > timing_only`.
- **Synthetic generator extension tests** (`tests/test_synthetic_traffic.py`): Determinism (same seed → same data), schema completeness (every sample has metadata + warrant + intervention labels), class-balance sanity check (intervention class distribution within ±10% of expected proportions).
- **Inference contract test** (`tests/test_temporal_warrant.py`): `predict_recommendations` returns a `RecommendationResult` with the correct field names, warrant_probs dict has all 6 expected keys with values in `[0, 1]`, intervention is one of the three valid strings, and confidence is in `[0, 1]`. Tested with a deterministically-initialized small model (not the trained one) so the test does not depend on training outcomes.
- **End-to-end evaluation harness as a "test" of the trained model**: The evaluation script (not a pytest test) functions as the model-quality gate. It must produce the multi-seed mean ± std AUC/F1 table, the confusion matrix, the ablation table, and the saliency figures. Reviewing this output is the acceptance gate before merging.
- **Prior art for the test style:** `tests/test_local_warrants.py` and `tests/test_recommendations.py` already establish the pattern of pure-function rule tests plus integration tests against a synthetic DB fixture.

## Out of Scope

- **Per-vehicle-type synthesis** (motorcycle, pedicab, tricycle splits). Required to predict W-Local 1 from the ML head - explicitly deferred. W-Local 1 remains a runtime rule in production code.
- **Replacing Webster's with a neural timing optimizer.** Considered (Option #6 / "neural Webster's") and explicitly rejected for this cut due to risk and effort. Future-work candidate.
- **Online forecasting** (LSTM/Transformer for next-15-min flow prediction). Already deferred in the parent plan; remains out of scope.
- **Corridor coordination across multiple intersections.** Already scoped out at the project level.
- **Real-CCTV transfer evaluation.** The thesis evaluates on synthetic data only. Real-data transfer is acknowledged as a limitation in the discussion chapter.
- **Operator approval workflow** (`tod_discovery_mode` column). Deferred in the parent plan; remains deferred.
- **Frontend redesign for intervention display.** A minimal change to render the new `intervention` field in the existing recommendation card is in scope; visual redesign is not.
- **Grad-CAM admin endpoint.** Saliency is generated offline by the evaluation script for thesis figures; surfacing it through an API is deferred.
