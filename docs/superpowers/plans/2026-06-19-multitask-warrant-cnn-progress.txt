        coverage for this task):
          widening + signalize eligible → widening wins
          widening + timing_only eligible (only widening) → widening
          signalize + timing_only eligible (only signalize) → signalize

        Boundary at vc == threshold (strict `>` is locked):
          vc == 0.90, no warrant → timing_only
          vc == 0.90, warrant met + unsignalized → signalize
            (precedence falls through because vc is not strictly above)
          vc == 0.9000001 → road_widening

        Custom threshold override:
          caller-supplied widening_vc_threshold replaces the default
          in both directions (lower threshold fires earlier; vc below
          the custom threshold falls through to signalize/timing_only).

        Return-value contract:
          parametrized check that the function always returns a label
          in INTERVENTION_CLASSES across all branches.

    1. GROUND_TRUTH_REGIMES trimmed from ~9× peak-to-off ratio (peak

       (~15–30%) rather than on almost every intersection.

    3. sample_intersection_modifier replaced. Was: uniform [0.8, 1.2]
       length-4 iid per approach. Now: a single per-intersection
       `scale ~ Triangular(0.25, mode=0.70, 2.30)` multiplied by a
       length-4 directional variation `~ Uniform[0.85, 1.15]`. The
       triangular's long upper tail is what drives the rare
       road_widening cases (vc > 0.90); the mode at 0.70 keeps the
       typical intersection in timing_only / signalize territory.

    Resulting class balance across seeds {0..9}, N=500 each:
       timing_only:     min 0.536, max 0.614, mean 0.588

    All seven new class-balance tests pass on seed=42 (the fixture seed)
    with timing_only=0.572, signalize=0.376, road_widening=0.052.

  Decisions:
    - Single per-intersection scalar (not 4 iid per-approach uniforms)
      was the necessary mechanism to extend the upper vc tail without
      pushing the median intersection up. With 4 iid uniforms, getting
      a high effective intersection-size requires all 4 approaches to
      draw high simultaneously (vanishing probability in the tail).
      The scalar variant matches the physical intuition: an
      intersection's size is one property, the per-approach directional
      asymmetry is layered on top.
    - Per-approach directional variation kept narrow (±15%) so the
      scalar-driven calibration is preserved; NB and SB can still
      differ by up to ~30%, which mirrors the AM-inbound / PM-outbound
      asymmetry already baked into the regime base.
    - Class-balance fixture is module-scoped (`scope="module"`) so the
      500-sample sweep runs once per file invocation rather than once
      per assertion — keeps the file under 0.5s total.
    - Class-balance bands are ±10pp around the PRD target rather than
      a hard "must equal" — the PRD itself names a 10% tolerance in
      §Testing Decisions and the test is meant as a regression guard,
      not a precision benchmark. Tighter bands would brittle-trip on
      any future calibration tweak the implementor wants to make.
    - W-Local 2 fire rate is 0.00 in the sweep. This is by design of
      the current parameter-realistic regime schedule: AM/MIDDAY/PM
      volumes are comparable enough that top-2 chunks total ≤70% of
      daily volume. W-Local 2's role in the dataset is exercised by

  Decisions:
    - Parameter count is 62,633 (default config), not the PRD's
      "approximately 50K". The 64→128 conv layer dominates at 41K params;
      shrinking it would compromise the receptive-field argument and
      change the channel-progression story in the methods chapter. Logged
      explicitly in the module docstring so the methods-chapter parameter
      table is unambiguous and future-me does not "fix" the count.
    - Sigmoid/softmax deliberately NOT in the model. PRD §Implementation
      Decisions / Outputs: "Sigmoid and softmax are applied at inference
      time, not in the model." Lets training pair the warrant head with
      BCEWithLogitsLoss (numerically stable vs. sigmoid+BCE) and the
      intervention head with CrossEntropyLoss (which expects logits).
    - Padding chosen as kernel_size//2 so each conv preserves temporal
      length before pooling. With kernel=5 (odd), this is exact "same"
      padding; the conv1→MaxPool(2)→conv2→MaxPool(2)→AdaptiveAvgPool
      chain reduces 96 → 48 → 24 → 1 deterministically. AdaptiveAvgPool
      means a different n_slots would still produce a (B, 128) flatten
      without arch changes — useful for the methods-chapter ablation
      that varies slot granularity.
    - inplace=True on the ReLU activations to trim memory; safe because
      the only branch points are after pooling (where the ReLU output
      is already consumed by the next conv).
    - BatchNorm placed before ReLU (the standard "conv → BN → ReLU"
      ordering) so the model can be trained with batch_size=1 only at
      eval time (BatchNorm in train mode requires batch_size ≥ 2).
      T12's training CLI uses batch_size=64 per PRD §Training procedure.
    - Default warrant_names / intervention_classes / metadata_features
      stored on the instance and returned by architecture_config(), so
      the checkpoint persists label semantics (not just the state_dict)
      and the inference loader (T10) can name the output dict without
      hard-coding the strings in two places.
    - conv_channels guarded with a "must have exactly 3 widths" check —
      the docstring + parameter-count table + methods-chapter diagram
      all assume three blocks. Tightening this here prevents a silent
      arch drift if a future caller passes a 2- or 4-tuple.
    - warrant_names / intervention_classes / metadata_features kept as
      separate optional args (not bundled into a single dict) so they
      can be omitted independently and so the checkpoint persists each
      one as its own architecture_config() key — same shape as the
      WarrantMLP checkpoint (input_features, warrants, hidden_dims).
