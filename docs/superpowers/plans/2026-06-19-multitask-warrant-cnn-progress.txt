2026-06-19 — T01 + T02 done (bundled because the PRD pairs each rule module
with its unit test suite under "Testing decisions"):

  Added:
    - server/warrant_rules.py
        IntersectionMeta dataclass (major_lanes, minor_lanes,
        posted_speed_kph, is_signalized, n_approaches).
        Helpers: _hourly_volumes (96-slot → 24-hour reduction),
        _major_minor_axes (volume-based NS-vs-EW axis assignment),
        _speed_factor (0.70 if posted_speed_kph ≤ 40, MUTCD §4C.01).
        MUTCD threshold tables for Table 4C-1 Conditions A and B as
        lane-count-keyed dicts.
        evaluate_w1 — eight-hour vehicular volume (Cond A OR Cond B,
        ≥ 8 qualifying hours, confidence = hours/8).
        evaluate_w2 — four-hour vehicular volume, piecewise-linear fit
        to Figure 4C-1 with minor-lane-dependent floor + intercept.
        evaluate_w3 — peak-hour curve ~150 vph above W2.
        evaluate_w4 — pedestrian volume (4-hour ≥ 107 OR 1-hour ≥ 133),
        low-speed factor applied to both thresholds.
        evaluate_all_mutcd — aggregate API returning
        {warrant_name: (met, confidence)}.

    - tests/test_warrant_rules.py
        20 pure-function tests covering helpers + each warrant's
        triggered / not-triggered / low-speed / lane-count behaviour
        + aggregate API. All 20 pass (verified locally on Python 3.12).

  Decisions:
    - File placed in server/ (next to local_warrants.py) rather than
      server/ml/ — these are rule evaluators, not ML code, and they
      mirror the existing W-Local 1/2/3 module's layout.
    - flow_matrix convention chosen: (5, 96), channels-first, with
      channel 4 = pedestrian crossing volume. Matches PRD §Implementation
      Decisions / Algorithmic centerpiece / Inputs.
    - Each slot value is treated as a PCU/hr rate (matching the existing
      synthetic-traffic generator's slot semantics from the parent plan);
      hourly volume = mean of 4 slot rates.
    - Figure 4C-1 and 4C-3 are encoded as piecewise-linear fits with
      lane-dependent floor/intercept rather than as digitized lookup
      tables, to keep the module dependency-free. Methods chapter will
      cite the figures and document the fit constants.

  Next: T03 (intervention_rules.py — assign_intervention_label).

2026-06-19 — T03 done (test suite T04 deferred to its own task per the
"one task at a time" instruction; this departs from the T01+T02 bundling
precedent on purpose):

  Added:
    - server/intervention_rules.py
        Module-level constants:
          INTERVENTION_CLASSES = ("signalize", "road_widening", "timing_only")
          DEFAULT_WIDENING_VC_THRESHOLD = 0.90  (per PRD §Synthetic data
            extensions / Intervention label assignment).
        Helper _any_warrant_met(warrant_results) — reads only the `met`
        boolean from each (met, confidence) pair, so the function works
        uniformly over MUTCD W1–W4 results from server/warrant_rules and
        W-Local 2/3 results from server/local_warrants.
        Public API:
          assign_intervention_label(
              critical_vc, is_signalized, warrant_results,
              widening_vc_threshold=DEFAULT_WIDENING_VC_THRESHOLD,
          ) -> str
        Precedence (locked):
          1. road_widening if critical_vc > widening_vc_threshold
          2. signalize     if (not is_signalized) and any warrant met
          3. timing_only   otherwise

  Decisions:
    - Strict `>` for the widening threshold (vc == 0.90 → timing_only or
      signalize, not widening). PRD wording is "v/c > 0.90"; chose strict
      to match. T04 tests will pin this boundary explicitly.
    - `warrant_results` typed as Mapping[str, tuple[bool, float]] rather
      than the dataclass-y custom type — matches the existing
      evaluate_all_mutcd return shape and local_warrants helpers exactly,
      so the same dict can flow straight from the rule modules into label
      assignment without re-packing.
    - Webster's is NOT run inside this module. The caller passes
      `critical_vc` already computed. Keeps the module DB-free and
      framework-free (it imports only `typing`); mirrors the
      pure-function tier of server/local_warrants._compute_w_local_*.
    - No DB, no SQLAlchemy, no Pydantic; placed in server/ next to
      warrant_rules.py and local_warrants.py to mirror their layout.

  Manual smoke check (python3 -c, not committed):
    widen on vc=1.05 → road_widening
    vc=0.5, unsignalized, w1 met → signalize
    vc=0.5, already signalized, w1 met → timing_only
    vc=0.5, unsignalized, no warrant met → timing_only
    vc=0.90 (boundary) → timing_only (strict >)
    vc=0.95 AND warrant met → road_widening (precedence verified)

  Next: T04 (tests/test_intervention_rules.py — unit tests for the three
  outcomes + pairwise-tie precedence checks).
