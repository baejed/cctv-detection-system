      server/ml/ — these are rule evaluators, not ML code, and they
      mirror the existing W-Local 1/2/3 module's layout.
    - flow_matrix convention chosen: (5, 96), channels-first, with

      synthetic-traffic generator's slot semantics from the parent plan);
      hourly volume = mean of 4 slot rates.
    - Figure 4C-1 and 4C-3 are encoded as piecewise-linear fits with
      lane-dependent floor/intercept rather than as digitized lookup
      tables, to keep the module dependency-free. Methods chapter will
      cite the figures and document the fit constants.

        Helper _any_warrant_met(warrant_results) — reads only the `met`

          assign_intervention_label(
              critical_vc, is_signalized, warrant_results,
              widening_vc_threshold=DEFAULT_WIDENING_VC_THRESHOLD,
          ) -> str
        Precedence (locked):
          1. road_widening if critical_vc > widening_vc_threshold
          2. signalize     if (not is_signalized) and any warrant met
          3. timing_only   otherwise

  Decisions:
    - Strict `>` for the widening threshold (vc == 0.90 → timing_only or
      signalize, not widening). PRD wording is "v/c > 0.90"; chose strict
      to match. T04 tests will pin this boundary explicitly.
    - `warrant_results` typed as Mapping[str, tuple[bool, float]] rather
      than the dataclass-y custom type — matches the existing
      evaluate_all_mutcd return shape and local_warrants helpers exactly,
      so the same dict can flow straight from the rule modules into label
      assignment without re-packing.
    - Webster's is NOT run inside this module. The caller passes
      `critical_vc` already computed. Keeps the module DB-free and
      framework-free (it imports only `typing`); mirrors the
      pure-function tier of server/local_warrants._compute_w_local_*.
    - No DB, no SQLAlchemy, no Pydantic; placed in server/ next to

2026-06-19 — T04 done:

  Added:
    - tests/test_intervention_rules.py
        24 pure-function tests, all passing. Coverage:

        Module-level constants:
          INTERVENTION_CLASSES is exactly the three locked labels
          (signalize / road_widening / timing_only).
          DEFAULT_WIDENING_VC_THRESHOLD == 0.90 (PRD value).

        Helper _any_warrant_met:
          true when any flag true; false for all-false and for {}.

        Each of the three outcomes:
          road_widening — vc > threshold (also dominates when already
            signalized, confirming widening is unconditional w.r.t.
            signal status).
          signalize — unsignalized + any warrant met + vc low. Tested
            parametrically over all six warrant names (w1–w4,
            w_local_2, w_local_3) to confirm the rule reads `any`,
            not a single warrant.
          timing_only — fall-through paths: no warrant met; already
            signalized even when a warrant is met; empty warrant dict.

        Three pairwise-tie precedence checks (the PRD's required
        coverage for this task):
          widening + signalize eligible → widening wins
          widening + timing_only eligible (only widening) → widening
          signalize + timing_only eligible (only signalize) → signalize

        Boundary at vc == threshold (strict `>` is locked):
          vc == 0.90, no warrant → timing_only
          vc == 0.90, warrant met + unsignalized → signalize
            (precedence falls through because vc is not strictly above)
          vc == 0.9000001 → road_widening

        Custom threshold override:
          caller-supplied widening_vc_threshold replaces the default
          in both directions (lower threshold fires earlier; vc below
          the custom threshold falls through to signalize/timing_only).

        Return-value contract:
          parametrized check that the function always returns a label
          in INTERVENTION_CLASSES across all branches.

  Decisions:
    - Test style mirrors tests/test_warrant_rules.py and
      tests/test_local_warrants.py — pure-function, no DB / FastAPI
      fixtures, small `_warrants(**flags)` builder for terse fixtures.
    - The strict-`>` boundary at vc == 0.90 is pinned explicitly in
      two tests (one falls through to timing_only, one to signalize)
      so any future loosening of the comparison would break both and
      force a deliberate PRD update.
    - The "signalize + timing_only tie" interpretation: there is no
      true tie between signalize and timing_only — they are
      mutually exclusive on whether (not is_signalized AND any
      warrant). The "tie" test covers the case where only signalize
      conditions are met (and not widening), which is the precedence
      check the PRD intended.
    - Also cleaned up two stray XML-ish tags (`</content>`,
      `</invoke>`) at the end of this progress file left over from
      an earlier write; not meaningful content.

2026-06-19 — T05 done:

  Added:
    - server/ml/synthetic_traffic.py
        Module-level constants:
          N_SLOTS = 96, N_VEHICLE_CHANNELS = 4, PED_CHANNEL_INDEX = 4,
          N_CHANNELS = 5.
          GROUND_TRUTH_REGIMES — parent-plan Phase 1 four-regime base
            (AM_RUSH, MIDDAY, PM_RUSH, OFF_PEAK) over (NB, SB, EB, WB)
            in PCU/hr; 9–10× peak/off-peak ratio cited as Tagum-typical.
          PED_PROFILES — new five-regime pedestrian schedule
            (AM_PED, LUNCH, PM_PED, DAY_LOW, NIGHT_LOW) in peds/hr.

        Schedule functions (pure, deterministic):
          regime_for_slot(slot)   — vehicle regime, 06–10 / 10–15 /
            15–19 / else.
          ped_regime_for_slot(slot) — pedestrian regime, 07:00–08:30
            AM, 11:30–13:30 LUNCH, 17:00–19:00 PM, then DAY_LOW for
            other waking hours, NIGHT_LOW overnight.

        Per-slot samplers:
          sample_flow_for_slot — ±10% Gaussian per-approach noise over
            the regime base, multiplied by a once-per-day modifier.
          sample_ped_for_slot — ±15% Gaussian (peds noisier than veh).

        Per-day flow matrix:
          generate_day_flow_matrix(rng, is_weekend=False,
              intersection_modifier=None) -> np.ndarray of shape
              (5, 96) dtype float64. Channels-first; matches
              server.warrant_rules' flow_matrix convention exactly.
          Weekend mode collapses AM_RUSH/PM_RUSH → MIDDAY and
            AM_PED/PM_PED → LUNCH, per parent-plan §Task 2 Step 3.

        Intersection metadata sampling (Tagum-realistic priors):
          _MAJOR_LANE_PROBS = {1: 0.40, 2: 0.60}
          _MINOR_LANE_PROBS = {1: 0.70, 2: 0.30}
          _SPEED_PROBS      = {30: 0.20, 40: 0.55, 50: 0.25}
          _APPROACH_PROBS   = {3: 0.20, 4: 0.80}
          _SIGNALIZED_PROB  = 0.25
          sample_intersection_meta(rng) -> IntersectionMeta (reuses the
            dataclass from server.warrant_rules so the sampled metadata
            slots straight into MUTCD evaluators).
          sample_intersection_modifier(rng) -> length-4 ndarray in
            [0.8, 1.2] for per-intersection variation.

  Decisions:
    - File placed at server/ml/synthetic_traffic.py per the parent
      plan's chosen location (Phase 1 Task 1) rather than alongside
      server/warrant_rules.py — keeps generator / model code under
      server/ml/ and rules under server/.
    - The base parent-plan Phase 1 logic (regimes, schedule, per-slot
      sampler, weekend variant, intersection modifier) is consolidated
      into this T05 module rather than landing as a separate prior
      module, because the parent plan's Phase 1 was not previously
      tracked as a discrete task in this progress log.
    - Reuses IntersectionMeta from server.warrant_rules so there is one
      source of truth for the dataclass shape. Importing back into the
      rules module is not done; metadata flows rules-direction only.
    - Pedestrian channel is generated with its own per-day modifier
      (independent from the vehicle modifier) so peds noise does not
      mirror veh noise — empirically peds and veh covary only weakly.
    - intersection_modifier influences vehicles only, not pedestrians;
      pedestrian volume is more a function of land use than of the
      vehicle scale of the intersection.
